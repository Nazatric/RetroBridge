# Architecture and status

RetroBridge is split so a later guest runtime can be developed without conflating “the CPU can decode ARM instructions” with “an Android app is compatible.” The current code is a safety-oriented foundation, not a finished compatibility runtime.

## Process and trust boundaries

- `:app` is the normal management process. It imports a selected base APK into app-private storage, keeps registry metadata, and displays explicit capability status. Its bounded APK-native ELF preflight reads only `.so` headers/program headers, checks ABI agreement and basic `PT_LOAD` ranges, and records warnings; it is not a linker or a loadability guarantee.
- `:core:runtime` contributes native `arm64-v8a` and `x86_64` libraries and declares a non-exported `GuestRuntimeService` in `android:process=":guest_runtime"`. A primitive-only `Messenger` protocol launches and stops bounded ARM32 native sessions. Before mapping a library, the service validates the guest identity and APK hash, extracts only `armeabi-v7a`/`armeabi` `.so` entries under per-entry/total quotas, verifies each extracted SHA-256, orders `DT_NEEDED` dependencies, and re-checks hashes at the JNI boundary. The native session maps ELF32 images, resolves only supported imports/thunks, executes constructors and valid `JNI_OnLoad`, then calls selected exported entrypoints under a guest-instruction budget. It returns real interpreter counters and diagnostics. No APK DEX/Java bytecode or Android Activity is launched; this process split is not a security boundary.
- `:core:manager` owns immutable guest metadata, an atomic JSON registry, and lifecycle transition validation.
- `:core:fs` owns the per-import filesystem layout, narrow guest-path mapper, quota-bounded streaming Android/data and OBB ZIP import, and SAF-export ZIP writer. It is not a mount namespace and does not grant access to arbitrary external storage.
- `:core:services` emits a capability report. It does not spoof PackageManager data or claim to provide Android framework services.
- `core/runtime/src/main/cpp` contains a sparse permission-checked guest memory map, an ELF32/ARM mapper and relocation subset, dynamic-symbol lookup, a bounded A32/T32 interpreter, guest SVC/trampoline hooks, lifecycle-function invocation, and an opaque handle table. A native session now connects these primitives for a deliberately limited subset of imported ARM32 shared libraries; it is not a general APK launcher.
- `native/` builds host-side verification tools and tests synthetic runtime code plus real ARM32 executable/shared-library fixtures cross-compiled by CI. The executable fixture is loaded, relocated, and run by the interpreter on the host.

## Important interfaces

### Guest address space

`GuestAddress32` and `GuestRange32` store guest addresses as `uint32_t` and check arithmetic in a wider integer type. `GuestMemory` maps sparse host-backed regions, enforces per-region read/write/execute permissions, and rejects unmapped or overflowing accesses; guest addresses are never cast to host pointers. `GuestHeap32` provides a bounded, aligned free-list allocator with coalescing and calloc/realloc/POSIX alignment semantics; allocator metadata is serialized, but this is not Bionic's allocator/debug interface, an OS page arena, signal-based fault boundary, or process sandbox.

### ARM execution

`TranslationEngine` is the execution-backend interface. `Arm32Interpreter` implements a deliberately explicit subset of A32 and T32 (including common integer/data-processing and branches, A32 halfword/signed-byte and aligned paired-register doubleword transfers, A32 `CLZ`, signed/unsigned 64-bit multiply/accumulate, Thumb-2 register-offset transfers, A32/T32 LDM/STM stack transfers, Thumb-2 MOVW/MOVT, SVC, VFP core/S-register transfers, and scalar VFP f32/f64 add/subtract/multiply/divide). `GuestCpuState32` carries R0-R15, CPSR/IT state, FPSCR, Q0-Q15, and guest TLS. Instruction budgets and guest-memory permissions are enforced. `GuestTrampolineRegistry` maps exported guest addresses/names to explicit host callbacks; it never exposes host function pointers to guest registers. `UnavailableTranslationEngine` remains a safe placeholder for a DBT backend that is not integrated. VFP conversions, VFP load/store and comparisons, vector/NEON operations, complete ARMv7 semantics, and general APK launch remain unsupported; only the explicitly selected shared-library entrypoints are invoked.

### Guest filesystem and syscalls

`NativeVfsPathTranslator` maps a strict set of Android private/internal, app-specific external, and OBB prefixes into an app-owned host root; it rejects traversal, package-prefix confusion, and symlink components. `NativeVfs` exposes virtual descriptors and uses directory-relative host calls without returning host paths or descriptor values to guest code. `Arm32SyscallDispatcher` converts selected ARM Linux EABI calls and fixed-width stat/time layouts, validates guest buffers, handles a subset of file/directory, clock, `mmap2`/`mprotect`/`munmap`, `brk`, and process calls, and returns `ENOSYS` for unknown calls. This is not a complete Linux kernel, thread scheduler, or shared-writable mmap implementation; it is wired to the selected native session but the host filesystem boundary still needs race-focused hardening.

### Bionic and guest symbol bridge

`GuestBionicThunks` registers address-based function trampolines and guest data cells, and exposes `resolve_guest_symbol()` for passing its supported function/data symbols to the ELF loader's external-symbol resolver. Its tested subset includes bounded guest-heap allocation, memory/string functions (including `memchr`, `memrchr`, `strnlen`, `strchr`, `strrchr`, `strstr`, `strpbrk`, `strspn`, and `strcspn`), ARM EABI helpers (including 64-bit multiply and shifts), and a selected libm/math-helper set, `open`/`openat`/`close`/`read`/`write`/`pread`/`pwrite`/`lseek`/`lseek64`, `mkdir`/`mkdirat`/`rmdir`/`unlink`/`unlinkat`/`rename`/`renameat`/`access`/`faccessat`/`stat64`/`lstat64`/`fstat64`/`fstatat64`, and `getdents64` through `NativeVfs`, `__android_log_write`, errno/stack-guard cells, and basic pthread mutex/TLS operations. `pthread_create` explicitly returns `EAGAIN`; it does not start a thread. A second lock by the single synthetic thread returns `EDEADLK` rather than blocking because there is no guest scheduler. Mutex ownership/attributes, condition variables, thread scheduling, per-thread errno/TLS, libc formatting/locale/stdio breadth, dynamic-loader semantics, and most Android/Bionic symbols remain unsupported. Guest string and memory operations are bounded and validate guest permissions. This bridge is wired into native sessions, but does not make the runtime compatible with arbitrary Android libraries.

### ELF loading and lifecycle

`Elf32Image::parse` validates little-endian ELFCLASS32 `EM_ARM` ET_DYN metadata and records DT_NEEDED/DT_SONAME. `Elf32Loader` maps PT_LOAD segments and permissions, parses dynamic symbols/hash tables, resolves symbols through a supplied callback, and applies a constrained ARM REL set. The native session orders dependencies, maps all app-private ARM32 libraries, then relocates against loaded images and selected thunks. Unsupported RELA/RELR/Android packed relocations, PT_TLS, IFUNC, and broad dynamic-linker semantics are rejected rather than guessed. `GuestLifecycleExecutor` retrieves validated DT_INIT/DT_INIT_ARRAY and DT_FINI_ARRAY/DT_FINI functions and calls them using a temporary return trampoline. Native tests cover A32/T32 constructors/destructors and session execution; emulator instrumentation also runs a signed ARM32 demo through the Android Messenger/JNI service.

### Guest references and NDK assets

`HandleTable` maps guest-width handles to opaque host tokens. `GuestJniBridge` allocates 32-bit `JNIEnv`/`JavaVM` tables in guest memory, registers address-based trampolines, implements a tested string/array/reference/local-frame/exception subset, and validates guest `RegisterNatives` descriptors and executable entry points. It has no ART, class loader, Java-method engine, callback scheduler, GC, modified UTF-8, or concurrency; unsupported table slots set an explicit pending exception. The session invokes and validates `JNI_OnLoad` through this synthetic table, but this is not a virtual Android Java runtime or general native-method dispatcher.

`GuestAndroidAssetThunks` exposes a bounded `AAssetManager_open`/`AAsset_read`/`AAsset_getBuffer`/seek/length/close subset over caller-registered immutable byte blobs. Asset handles are generation-checked opaque guest values; `getBuffer` materializes bytes in the bounded guest heap, paths reject traversal, and blob/catalog sizes are capped. The separate host-only `GuestContextWrapper.readAsset()` can read one bounded APK ZIP entry, but it is not connected to these C++ thunks; Java `AssetManager` conversion and asset-directory APIs remain unsupported. `GuestAndroidWindowThunks` provides host-created offscreen RGBA_8888 surfaces with the 32-bit `ANativeWindow_Buffer` ABI, geometry, lock/unlock-and-post, and reference-count thunks. These surfaces are not connected to Java `Surface` or a display. `GuestAndroidInputThunks` exposes a host-injected bounded key/motion queue, guest event handles/accessors, and a nonblocking per-runtime ALooper wake/timeout subset. There is no Android input source, queue-to-looper attachment, callback dispatch, or fd polling. `GuestHeadlessGlesEglThunks` adds a synthetic window-surface/context path and software `glClearColor`/`glClear`/scissor implementation directly over guest pixel memory; it keeps one non-thread-local current context and has no draw calls, shaders, textures, framebuffers, pbuffer surfaces, or Android display integration. `GuestOpenSlThunks` provides Android OpenSL ES 1.0.1-compatible guest object/interface vtables and engine-interface query entrypoints for a shared reference-counted engine, output mix, PCM queue player, play-state control, and bounded host-drained buffers. Standard engine options are recognized as no-ops; there is no Android audio sink, recording, or callback dispatch.

### Runtime IPC and guest context

The app UI binds to the non-exported service with `GuestRuntimeClient` and sends only primitive identity and imported manifest metadata through `Messenger`; it never passes a host `Context`, file descriptor, or host pointer. The service runs requests on its own `HandlerThread`, caps request sizes/session count, and returns correlated status/diagnostic replies. `GuestRuntimeSessionSupervisor` makes start idempotent and tears down sessions explicitly. A host-only `GuestContextWrapper` prepares guarded private/cache/external/OBB directories, performs no-follow private-file opens, stores bounded typed preferences, and reads one bounded APK ZIP asset; its `GuestPackageManager` exposes only the imported package snapshot. Neither class extends Android framework APIs or dispatches guest Java calls. A running session owns a C++ interpreter, guest memory/heap, private VFS, syscall dispatcher, selected Bionic/JNI/NDK thunks, and mapped shared libraries. `guestCodeStarted` is true only when interpreter instructions actually ran; the UI reports executed instructions, relocations, loaded libraries, JNI version/native-registration count, and supported entrypoint results. There is no Activity/Service proxy, Java class loader, system PackageManager/Resources/AssetManager virtualization, permission model, guest Binder bridge, DEX execution, or full Android lifecycle.

### Persistence and per-app storage

Each import gets `RetroBridge/apps/<package>/<uuid>/` so separate imports cannot reuse a mutable root. The manager stores only normalized paths relative to RetroBridge's private data root. Registry writes use a same-directory temporary file and atomic replacement when supported. The host-side `GuestContextWrapper` maps the selected guest's files, cache, no-backup, code-cache, external-files/cache, OBB, and shared-preferences directories; its file and asset names are bounded and validated against the private roots. `GuestPreferences` uses a versioned, size-capped binary format with atomic replacement, not Android XML or cross-process `SharedPreferences` semantics. The storage layer rejects traversal, unknown roots, and symlink components.

## Roadmap (gates, not promises)

1. Keep import, registry, path isolation, capability reporting, and ABI diagnostics tested.
2. Expand the interpreter subset; add cross-compiled instruction/ABI tests and harden unsupported-instruction behavior.
3. Continue linker work (TLS, symbol versioning, broader relocation support) and fuzz all untrusted ELF/ZIP paths.
4. Expand syscall/VFS coverage, harden host path race handling, and add guest ABI layout tests; never pass host pointers or host `long`/`size_t` layouts through guest registers.
5. Expand synthetic JNI/JavaVM and Bionic/NDK subsets; add callbacks, assets, native windows, scheduling, and cross-ABI tests only behind explicit capability reporting.
6. A CI-built signed/zip-aligned demo APK now exercises import, the real JNI bridge, load, execution, VFS writes, and teardown through `:guest_runtime` on an API 35 x86_64 emulator. Continue to label the feature a bounded native subset, not a general APK launch.

A completed earlier gate does not imply that a later gate or general Android framework compatibility is available.
