# Compatibility matrix

This matrix describes what the current tree implements. “Available” means the listed narrow operation is present; it is not a claim that arbitrary Android software runs.

| Area | Current status | Boundaries |
| --- | --- | --- |
| Import a single APK | Partial | Copies a document-provider selection to private storage, hashes it, reads package/version/SDK metadata, and catalogs `.so` files inside the APK. A bounded preflight checks library path/ABI agreement, ELF class/endianness/machine/type/version, and bounded `PT_LOAD` table/ranges. Import itself does not extract or execute native entries; the separate explicit launch action extracts only bounded ARM32 libraries, re-hashes them, and interprets the supported subset. Passing preflight is not proof of linkability or loadability. Split APKs and package installation are not implemented. |
| Management UI and diagnostic history | Partial | Distinguishes Imported from a selected native-runtime result; import/preflight does not show Ready. Lists per-app ABIs/libraries, supports data/OBB operations, and can attempt only the bounded ARM32 native path. The Diagnostics screen searches and filters by severity/category/component/app, expands details, groups repeats with counts, and exports filtered JSON. Runtime outcomes are persisted in launch history and a bounded event log; there is no persisted “Ready” certification. The UI does not execute guest Java/DEX or launch Activities. |
| Runtime IPC and guest context | Partial | A non-exported Messenger service validates identity/hash, receives the imported manifest metadata snapshot, extracts only bounded ARM32 `.so` entries into app-private storage, re-hashes each library, and manages interpreter sessions with native teardown. A host-only `GuestContextWrapper` exposes guarded private/cache/external/OBB paths, private files, typed persistent preferences, and bounded reads of base-APK `assets/`; `GuestPackageManager` returns metadata for only the selected guest. These helpers are not Android `ContextWrapper`/`PackageManager` implementations and guest Java cannot call them. The process shares the app UID and is not a general execution sandbox. |
| Android/data ZIP import | Available | Streams into private temporary storage, enforces compressed/uncompressed byte and entry quotas, validates optional package-qualified roots, rejects traversal/duplicate paths/Unix symlinks, and commits with rollback. This is data import, not Android app installation. |
| OBB import and export | Available | Imports one package/version-qualified `.obb` or ZIP bundles of associated OBBs with quotas and path/symlink checks. SAF ZIP export streams guest internal/external/OBB files and a JSON manifest. |
| Registry | Available | App-private JSON registry, record/path validation, and atomic replacement. It is not encrypted and relies on Android's normal application sandbox. |
| Structured diagnostics | Partial | Kotlin runtime stages classify stable severity/category/code/component/operation/app fields with actionable next steps, preserving raw details and relevant library/file/symbol/PC/opcode when available. The app-private history is bounded to 500 groups, coalesces identical events for 60 seconds while preserving counts, supports UI search/filter and filtered JSON export, and keeps up to 200 launch outcomes per app. Native C++ diagnostics are still bounded strings classified at the runtime boundary; process death or storage failure can prevent persistence. |
| ARM32 ELF identification | Available | Host validator accepts supported ELF32 little-endian `EM_ARM` ET_EXEC/ET_DYN metadata; CI uses actual NDK-produced ARM32 executable and shared-object fixtures. |
| ELF segment loading, dependency order, and relocations | Partial | Maps bounded ET_DYN PT_LOAD regions with guest permissions, parses dynamic/hash tables and DT_NEEDED/DT_SONAME, topologically orders packaged dependencies, resolves supported exports/thunks, and applies a reviewed ARM REL subset. RELA/RELR/Android packed relocations, IFUNC/TLS/symbol versions, and a full dynamic linker are unsupported. |
| Bounded ARM32 native-library launch | Partial | Extracts ARM32 shared objects from the verified APK, enforces size/count caps and SHA-256, maps and relocates dependencies, runs constructors, validates `JNI_OnLoad`, calls only `retrobridge_main`, `retrobridge_entrypoint`, or `main` when exported, and reports instruction/relocation/lifecycle results. A CI-built signed/zip-aligned demo APK verifies this path through the real Android Messenger/JNI service on an API 35 x86_64 emulator. No APK DEX/Java code, Android Activity, or arbitrary native symbol is launched. |
| ELF lifecycle functions | Partial | Validates DT_INIT/DT_INIT_ARRAY and DT_FINI/DT_FINI_ARRAY addresses and invokes them through a temporary guest return thunk during native-session launch/stop. Host CTest and Android emulator instrumentation both verify constructors/destructors; the demo test checks that the destructor appends its VFS line after session stop. |
| A32/T32 instruction execution | Partial | A bounded interpreter executes explicit integer/branch/load-store subsets including A32 `STRH`/`LDRH`/`LDRSB`/`LDRSH` with immediate/register offsets and pre/post-index writeback plus aligned paired-register `LDRD`/`STRD`, A32 `CLZ`, signed/unsigned 64-bit multiply/accumulate instructions (`SMULL`/`UMULL`/`SMLAL`/`UMLAL`), A32 and T32 LDM/STM stack transfers (including high-register restore and Thumb PC return), Thumb-2 register-offset word/byte/halfword loads and stores (including signed loads), MOVW/MOVT, SVC/trampolines, VFP core/S-register transfers, and scalar f32/f64 add/subtract/multiply/divide; CTest covers these hand-encoded paths and a real NDK-built VFP fixture. VFP conversion/load-store/compare, vector/NEON, and broad architectural corner cases are unsupported; this is not a complete ARM CPU or DBT. Fault reports preserve guest PC and opcode/halfword where instruction fetch succeeded; a native regression asserts unsupported `MUL PC` is a fault and is never emulated. |
| Guest heap | Partial | A bounded 32-bit allocator supports aligned allocation, calloc/realloc/free, coalescing, and POSIX alignment validation. The Bionic thunk table maps basic allocator calls to it. This is not Bionic's allocator/debug interface or a process heap with full per-thread semantics. |
| Guest VFS and Linux EABI syscalls | Partial | The native session wires a POSIX-backed descriptor layer to internal/external/OBB roots, rejects traversal/symlink components, and implements tested file I/O, stat/directory basics, clocks, `mmap2`/`munmap`/`mprotect`, `brk`, and selected process calls. Writable shared mappings, full `*at`/futex semantics, many syscalls, and many libc wrappers remain unsupported; unknown syscalls return `ENOSYS`. This is not a kernel sandbox. |
| Bionic/libc/libm/pthread/C++ ABI | Partial | `GuestBionicThunks` is wired into sessions and exposes bounded allocation/memory/string helpers including `memchr`, `memrchr`, `strnlen`, `strchr`, `strrchr`, `strstr`, `strpbrk`, `strspn`, and `strcspn`, plus ARM EABI routines including 64-bit multiply and shifts, and a selected libm set, VFS open/openat/read/write/pread/pwrite/fsync/fdatasync/seek plus mkdir/mkdirat/rmdir/unlink/unlinkat/rename/renameat/access/faccessat/stat64/lstat64/fstat64/fstatat64/getdents64 wrappers, a guest `__android_log_write` sink, errno/stack-guard cells, and basic mutex/TLS-key calls. `pthread_create` returns `EAGAIN`. A narrow C++ ABI shim provides guest-heap `new`/`delete` and single-threaded `__cxa_guard_*` local-static initialization with a 4,096 in-progress-record bound; `libstdc++.so` is a virtual dependency rather than a loaded DSO; imports resolve only from APK-local libraries or the explicit thunk table. There is no guest scheduler, condition-variable API, complete per-thread errno/TLS, C++ atexit registry, exception unwinding, general stdio/locale support, or broad Android symbol coverage. Unsupported imports fail during relocation. |
| JNI/JavaVM | Partial | A synthetic 32-bit `JNIEnv`/`JavaVM` table is wired into sessions; `JNI_OnLoad` receives the guest JavaVM, its returned version is checked, and `RegisterNatives` metadata is counted. String/array/ref/exception subsets are tested. Native methods are not dispatched to a Java runtime; there is no ART, DEX, Java callback engine, class loader, GC, full JNI table, modified UTF-8, or concurrent JNI calls. |
| NDK AAssetManager/AAsset | Partial | `AAssetManager_open`, bounded `AAsset_read`, `AAsset_getBuffer`, seek/length, and close thunks use caller-registered immutable blobs. The host-only context facade can read one bounded APK ZIP asset, but that catalog is not connected to the C++ thunks; Java `AssetManager` conversion and asset-directory APIs remain unsupported. |
| Headless ANativeWindow buffer subset | Partial | Host-created surfaces expose separately mapped RGBA_8888 guest pixel buffers (4 Mi pixels and 4096 pixels per side per surface, 16 MiB aggregate cap) with 32-bit `ANativeWindow_Buffer` layout, lock/unlock-and-post, geometry, and acquire/release. There is no Java `Surface`, Android display compositor, or automatic app/window lifecycle connection. |
| Synthetic AInputQueue and ALooper subset | Partial | Host-injected bounded key/motion events are dequeued through guest handles with selected accessors and finish semantics. ALooper supports a per-runtime prepare/wake and nonblocking wake/timeout poll; there is no Android input source, thread-local looper, queue attachment, callback dispatch, or fd polling. |
| Headless EGL/GLES clear subset | Partial | A synthetic EGL display/config/context and window surface render RGBA_8888 `glClearColor`/`glClear`, viewport/scissor state, basic error/string queries, and `eglSwapBuffers` into bounded guest memory. `libGLESv3.so` is accepted only as a virtual dependency name; no host/system DSO is loaded, and each imported symbol must still resolve to an APK-local export or an implemented thunk (currently a clear-only GLES subset). This does not implement GLES 3 or a GPU. Only one non-thread-local current context is supported. No shaders/draw calls, textures/buffers, FBOs, pbuffer surfaces, broad GLES, or Android display integration. |
| OpenSL ES PCM buffer-queue subset | Partial | The synthetic Android OpenSL ES 1.0.1 ABI is installed in sessions and supports selected interface IDs, engine/player lifecycle, play state, and bounded host-drained PCM queues. It has no Android audio sink, real-time playback/recording, guest callback dispatch, volume/effects, or audible output. |
| Android framework | Not implemented | No Activity/Service proxy, Android `ContextWrapper`, system `PackageManager`/`Resources`/`AssetManager` virtualization, permission model, Java class loading/DEX, Android lifecycle callbacks, or guest Binder bridge is implemented. The host-only context facade exposes a guarded storage/asset subset and one imported package metadata snapshot; it is not callable by guest Java code. |
| Rootless data isolation | Partial | App-private per-import directories and guarded path mapping exist. This is not kernel isolation, a process-level guest sandbox, or a safe execution boundary for native guest code. |
| Privileged/system integration | Out of scope for this prototype | Device-wide ABI reporting, system linker changes, and global package visibility cannot be promised to a standard unprivileged app. |

## Why ARM32 ABI detection is not compatibility

An APK may contain valid ARM32 machine code and still require unsupported linker symbols, Android framework APIs, Bionic behavior, kernel syscalls, graphics/audio services, or native libraries. RetroBridge can execute only a narrow selected ARM32 native subset; successful ELF preflight does not guarantee launch, and a successful native subset run does not imply that the Android app as a whole is compatible.
